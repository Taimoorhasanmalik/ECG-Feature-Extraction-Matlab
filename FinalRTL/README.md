# Final adaptive ECG RTL package

This folder is a standalone source snapshot of the selected two-stage design.
It does not need the MATLAB databases, model MAT files, floating-point IP,
or any other repository folder to synthesize. Model coefficients are in RTL.

## Selected hardware

- Basys 3 Artix-7 `xc7a35tcpg236-1`, top `basys3_two_stage_adaptive_top`.
- 100 MHz source; independent 120 samples/s input acquisition.
- Whole processing clock: 500 Hz asleep; 100 kHz while Stage 2 is armed/draining.
- `ADAPTIVE_CLOCK=1`, `STAGE1_FULL_RATE=0`, `CLOCK_GATING=1`.
- Core selects `SHARED_HP1_MODEL=1`, `DEEP_HISTORY=0`.
- Separate warm 5 Hz/1 Hz filters and per-stage streaming-statistics state.
- Shared 240/120 sequencer, 240 x 32 two-lane history, replay engine and MAC.
- Stage 2 arms on 2-of-3 abnormal votes; two normal sequence decisions disarm
  new starts. Started windows finish/report before the processing clock slows.

## Folder contents

```text
FinalRTL/
  rtl/                 12 synthesis source files and explicit files.f
  constraints/         Basys 3 pin/timing constraints
  mem/                 1200-sample synthetic demo ROM initialization
  sim/                 Simulation-only clock models, divider and smoke tests
  add_files.tcl        Add sources to an open project, or create/open one
  check_synthesis.tcl  Synthesize, check clocks/black boxes, optimize/check DRC
  SOURCE_MANIFEST.md   Canonical source mapping and snapshot checksums
  reports/             Synthesis reports generated by verification
```

The synthesis list deliberately excludes testbenches and clock-buffer
substitutes. `stage2_filter_q29.v` and `stage2_classifier_gated_q.v` are included
to keep referenced compatibility module definitions resolved; they are not
the selected Stage 2 filter/MAC datapath. The alternate filter generate branch
is inactive, and the unused classifier instance is optimized out. The selected
filter is `stage2_shared_hp1_q29`; scoring uses `shared_classifier_mac_q`.

## 1. Add the design to Vivado

In the Vivado Tcl console, with an empty/compatible project open:

```tcl
source {E:/Thesis/ECG-Feature-Extraction-Matlab/FinalRTL/add_files.tcl}
```

Use the package's location if you move it. Paths inside the script are resolved
relative to the script, not the console's working directory. With no project
open, it creates/opens `vivado_project/final_ecg.xpr` in this folder. The script
sets the board top and selected generics and leaves the project open in the GUI.

It does not delete unrelated files or silently replace a different copy of a
same-named source. A conflicting source or wrong FPGA part produces an error;
use an empty project or resolve the conflict explicitly. Existing unrelated
module definitions under different filenames are not automatically detected.
Do not mix another version of this architecture into the same source set.

## 2. Check synthesizability

In the Vivado Tcl console, with no synthesized/implemented design open:

```tcl
source {E:/Thesis/ECG-Feature-Extraction-Matlab/FinalRTL/check_synthesis.tcl}
```

Or from PowerShell at the repository root:

```powershell
& 'C:\Xilinx\Vivado\2020.2\bin\vivado.bat' -mode batch -source .\FinalRTL\check_synthesis.tcl -nojournal -nolog
```

For an installation already on PATH:

```text
vivado -mode batch -source /path/to/FinalRTL/check_synthesis.tcl -nojournal -nolog
```

The script performs direct project-context `synth_design`; it does not require
`launch_runs` or a Windows Script Host run wrapper. The synthesis status
`FINAL_RTL_SYNTHESIS_PASS` confirms no unresolved black boxes and verifies
the 100 MHz, 100 kHz and 500 Hz constraints. It then runs the normal
`opt_design` cleanup and checks post-optimization DRC errors. This requires
Vivado's implementation feature as well as synthesis. Success also prints
`FINAL_RTL_OPTIMIZATION_PASS`. Raw synthesis and optimized reports/checkpoints
are kept separately in `reports/`. Re-running replaces those package-generated
files. Check tool errors as well as both final status messages.

Synthesis does not establish routed timing, CDC/reset correctness, power
savings, ASIC synthesis portability, or on-board functionality. The design uses
Xilinx `BUFG`/`BUFGCE` primitives; Vivado supplies their device definitions.
The board XDC is specific to the board top. If using `two_stage_adaptive_clock_top`
as an external-ADC integration top, supply an appropriate integration XDC;
do not apply these board pin/hierarchy constraints unchanged.

The public data interface is 32-bit signed Q16.16 with a source-domain valid
strobe and mailbox ready/overflow status. Respect the periodic 120 Hz contract.
Classification outputs are in the processing domain and need a suitable host
capture/CDC interface. Board switches/buttons are only a demonstration source.

## 3. Xcelium preparation

Xcelium is a simulator, not the Vivado FPGA synthesis tool. Xcelium has not yet
been executed for this package. The source list and tests below are supplied
for a subsequent Cadence run; the simulation-only models are not a claim of
validated Xilinx device timing or clock-gate startup behavior.

From inside this folder on the machine with Xcelium installed:

```sh
cd /path/to/FinalRTL
xrun -64bit -sv -timescale 1ns/1ps -f sim/divider.f -top adaptive_clock_tb
xrun -64bit -sv -timescale 1ns/1ps -f sim/smoke.f -top two_stage_adaptive_smoke_tb
```

Run each command separately. Both use relative file lists, so use this folder
as the working directory. The smoke test reads
`mem/synthetic_two_stage_demo_q3_8.mem`; override with `+MEM_FILE=/absolute/path`
if needed. It uses a 200 kHz source for simulation speed, retaining 500 Hz /
100 kHz processing and 120 Hz input. The divider unit test uses the real
100 MHz source. The smoke test checks accepted samples, result codes, both-stage
activity, fast entry and overflow; it is not a bit-exact or clinical-accuracy
regression and does not prove drain/re-wake coverage.

`sim/clock_primitives_sim.v` supplies behavioral BUFG/BUFGCE models for portable
RTL testing. They must never be added to the Vivado synthesis source list.
Alternatively, use properly compiled Xilinx simulation libraries and exclude
these substitutes; never compile both definitions together. Device-accurate
simulation requires the vendor library and its documented setup.

Cadence's command-line entry point is `xrun`; see the official
[Xcelium command-line overview](https://support1.cadence.com/public/docs/content/20516593.html).
For complete sample-span/reference regression, the canonical verification
suite remains in `final_two_stage_design/hardware/`; it is not required to
synthesize or run the package's standalone smoke test.

## Verification record - 2026-10-11

The standalone package was tested directly with Vivado 2020.2 on
`xc7a35tcpg236-1`. No hardware logic was changed to package it.

| Check | Result |
| --- | --- |
| Copied source/constraint/memory/model text | All 16 copied files match canonical text after line-ending normalization |
| Source list | 12 RTL files, 14 module definitions; no duplicate module names |
| Project-context synthesis | Passed; no unresolved black boxes, no synthesis errors or critical warnings |
| Constraints | 100 MHz source and both 100 kHz / 500 Hz processing modes present |
| Internal clock coverage | Zero unclocked registers and zero unconstrained internal endpoints |
| Normal post-synthesis optimization | Passed |
| Post-optimization DRC | No errors or critical warnings; warnings remain |
| XSim actual-source divider test | Passed: 8 slow and 27 fast complete half-cycles, no runt pulses |
| XSim integration smoke | Passed: all 1200 samples accepted; 3 Stage 1 sequence reports, 4 Stage 2 reports, 1 fast entry; no overflow |
| Xcelium execution | Not run; prepared file lists/models/tests only |

Resource reports are build-stage specific, not routed area measurements:

| Stage | LUTs | Flip-flops | DSP48E1 | RAMB18E1 | Global clock resources |
| --- | ---: | ---: | ---: | ---: | ---: |
| Raw synthesis | 5301 | 2402 | 48 | 2 | 5 |
| After `opt_design` | 5293 | 2403 | 48 | 2 | 4 |

Raw `synthesis_drc.rpt` includes a `PLCK-1` clock-placement error caused by the
unused compatibility classifier gate before cleanup. Normal `opt_design`
removes that unused gate, and `optimized_drc.rpt` has no errors. No clock-route
waiver was applied. DSP pipelining and `REQP-1840` asynchronous RAM-control
warnings remain and require interpretation/review before production sign-off.
Vivado also reports primitive architecture translation and synthesis-unsupported
hold-only constraint warnings; implementation applies the latter constraint.

The raw, unplaced synthesis timing report has setup WNS +4.995 ns but hold WHS
-0.197 ns. These estimates do not establish routed timing closure; hold fixing
and physical clock placement require implementation. This package check did
not place/route, generate/program a bitstream, measure power, or rerun clinical
accuracy validation.

The portable testbenches were compiled and executed with the package's
behavioral clock models in XSim. This verifies those tests locally, not Cadence
compatibility or device-accurate primitive timing. For XSim reproduction from
inside this folder, with Vivado tools on PATH:

```text
xvlog --sv -f rtl/files.f sim/clock_primitives_sim.v sim/adaptive_clock_tb.sv sim/two_stage_adaptive_smoke_tb.sv
xelab adaptive_clock_tb --snapshot adaptive_clock_tb --timescale 1ns/1ps
xsim adaptive_clock_tb --runall
xelab two_stage_adaptive_smoke_tb --snapshot two_stage_adaptive_smoke_tb --timescale 1ns/1ps
xsim two_stage_adaptive_smoke_tb --runall
```

Use the default relative memory path when invoking these Windows launchers;
the Xcelium `+MEM_FILE=...` override is independent of their argument handling.
