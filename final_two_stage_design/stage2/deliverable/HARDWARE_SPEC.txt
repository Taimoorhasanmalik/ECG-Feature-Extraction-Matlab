STAGE 2 VT-vs-VF HARDWARE IMPLEMENTATION SPEC (120 Hz variant)
===============================================================

Input: single-channel ECG, sampled at 120 Hz -- the SAME rate as Stage 1, chosen so both
stages can share one ADC/clock feed with no divider. Source recordings (VFDB/CUDB) are
natively 250 Hz; resample to 120 Hz before anything else (see open item on anti-aliasing).

1. PREPROCESSING (per record, streamed causally)
   a. Detect WFDB format-212 dropout sentinel (digital code -2048) if reading raw WFDB;
      for a live ADC, apply whatever this system's own dropout/saturation detection is.
      Interpolate detected dropouts (linear between valid neighbours; hold flat before
      the first / after the last valid sample).
   b. Remove baseline: causal single-pole (1st-order Butterworth) highpass at 0.1 Hz --
      NOT a whole-record median (non-causal, unrealizable on a live stream). See
      signal_format.baseline_removal for the verification behind this choice.
   c. Quantize to Q5.8 (5 integer bits, 8 fraction bits, truncate toward zero, clamp to
      [-32, 31.996]). NOT Q3.8: the DC blocker's own output has real overshoot (worst
      case 8.9-9.9 across a 0.02-0.5 Hz cutoff sweep) that a narrower format would clip.
   d. Apply the causal 0.5-40 Hz bandpass filter (4 cascaded biquads below), forward only.
   e. Quantize the filtered output to the SAME Q5.8 (5 integer bits, 8 fraction bits, range
      [-32, 31.996]) used in step (c) -- one uniform wide format at both points instead of
      a patchwork of widths. The filter has real gain/overshoot that regularly exceeds its
      own input range (worst case 13.7 across the 49-record pool); a narrower Q3.8 here
      silently clipped inside a real held-out test window in an earlier version of this
      pipeline. See signal_format.post_filter_rationale.

2. FILTER (causal, 4th-order Butterworth 0.5-40 Hz bandpass = 8th-order / 4 biquads)
   Coefficients are float64 in this deliverable -- NOT yet quantized (open item).
   Each row: [b0 b1 b2 a0 a1 a2], apply in sequence (a0 = 1 for every section):
     section 1: [0.2252932878 0.4505865755 0.2252932878 1 0.5436087485 0.1090026967]
     section 2: [1 2 1 1 0.7508557746 0.5066020574]
     section 3: [1 -2 1 1 -1.951590689 0.9522773201]
     section 4: [1 -2 1 1 -1.979693669 0.9803752337]

3. WINDOWING
   2.0 s window (240 samples), 1.0 s stride (120 samples).

4. FEATURES (7, computed per window on the Q5.8-quantized filtered signal, in this order)
   1. mean_abs_amp               [Q3.8]
      mean(abs(window - mean(window)))
   2. line_length                [Q8.8]
      sum(abs(diff(window - mean(window))))
   3. derivative_zero_crossings  [Q8.0 (integer count, no fraction bits)]
      sign changes in diff(centered), after discarding samples with |value| <= 0.05*mean(|diff(centered)|)
   4. threshold_crossings        [Q8.0 (integer count, no fraction bits)]
      count of crossings of abs(centered) >= 0.20*max(abs(centered))
   5. local_amp_mean             [Q3.8]
      mean over 8 blocks of 0.25s (30 samples each, exact -- covers the full 240-sample window with no leftover, unlike 250 Hz's 496-of-500) of mean(abs(centered)) per block
   6. local_amp_range            [Q3.8]
      max block mean minus min block mean (same 8 blocks)
   7. amp_transition             [Q3.8]
      mean absolute difference between consecutive block means

   Why these Q-formats (every feature is now fully specified, not just the signal and
   classifier weights): Sized from each feature's own observed range across the full 49-record candidate pool (mean_abs_amp/local_amp_mean max 4.17, local_amp_range max 5.14, amp_transition max 1.56 -- all comfortably inside Q3.8's +-8 range on their own -- narrower than the Q5.8 signal format, since these are per-window statistics, not raw filter output with overshoot risk. line_length reaches 186 (needs Q8.8's wider integer headroom, same fraction width as the signal). derivative_zero_crossings (max 115) and threshold_crossings (max 81) are counts by construction -- Q8.0 needs no fractional hardware at all, just a wide-enough integer register. The classifier was retrained on these quantized feature values (not just re-quantized after the fact), and held-out accuracy was unchanged (0.9510, identical to the float baseline) -- the quantization error is at most 1/256 for the amplitude features and exactly zero for the two counts, which are already integers.

   Why all 7 are kept despite derivative_zero_crossings and threshold_crossings having small
   learned coefficients: An ablation on the same held-out set found derivative_zero_crossings contributes no measurable accuracy change if dropped (0.9608 with or without), while threshold_crossings is load-bearing (dropping it costs 0.9608 -> 0.9559 accuracy and 0.80 -> 0.77 VT recall) despite having a similarly small learned coefficient. Both are kept anyway: Stage 1's own base model already computes zero_crossings and threshold_crossing_count as two of its four features, so the counter/comparator hardware for this class of feature is already required elsewhere in the design -- keeping both here reuses that same cheap primitive on a second signal path rather than adding new hardware, so there is no cost to keeping the one (derivative_zero_crossings) that showed no measured benefit on this test.

5. CLASSIFIER
   score = dot(features, weight) + bias;  predict VF if score > 0, else VT.
   Weight format: Q2.13 (2 integer bits, 13 fraction bits). Bias: same format.

   feature                    weight (float) weight (Q2.13)
   mean_abs_amp                    -0.926347      -0.926270
   line_length                      0.023114       0.023071
   derivative_zero_crossings       -0.000225      -0.000122
   threshold_crossings              0.000382       0.000366
   local_amp_mean                  -0.926123      -0.926025
   local_amp_range                 -0.635825      -0.635742
   amp_transition                   0.152135       0.152100
   bias                             0.998613       0.998535

6. WHY Q2.13 FOR THE WEIGHTS (NOT Q5.8, the signal's own format)
   The combined weights range from ~0.002 to ~1.38 in magnitude -- an unrelated dynamic
   range from the signal itself, set by training, not by ECG voltage scale. At Q5.8's
   resolution (1/256 = 0.0039), 2 of 7 weights are below one LSB and truncate to exactly
   zero -- silently dropping those features from the decision entirely. Q2.13's finer
   resolution (1/8192, ~32x finer) preserves them, at the cost of less integer headroom
   (max representable ~4.0, comfortably above the largest observed weight of 1.38).
   Measured on the same 204 held-out windows: float64 accuracy 0.9510, Q2.13 accuracy 0.9510
   (delta +0.0000), Q5.8 accuracy 0.9461 (delta -0.0049).

7. VALIDATION PROVENANCE
   Trained on 34 records; held out entirely (never trained on): vfdb/429, vfdb/615, cudb/cu13, cudb/cu32
   Dropped from consideration: vfdb/610 (only 4 windows), cudb/cu18 (consistent poor
   performer across every diagnostic in this project).
   Held-out (genuinely unseen) accuracy: 0.9510 -- independently reproduced in Python,
   MATLAB float inference, and MATLAB fixed-point inference, with zero prediction
   disagreement between them.

8. OPEN ITEMS (not yet resolved)
   - Filter (SOS) coefficients are still float64, not quantized -- coefficient quantization can shift pole locations and was not tested here.
   - RESOLVED (was open in the 250 Hz deliverable): sample rate now exactly matches Stage 1's 120 Hz, so both stages can share one ADC/clock feed.
   - RESOLVED: the 7 feature values themselves now have explicit, validated Q-formats (see section 4), not just the signal and the classifier weights -- retrained and re-validated end to end with zero accuracy loss.
   - RESOLVED: baseline removal was a non-causal whole-record median (impossible on a live stream) -- replaced with a causal single-pole 0.1 Hz highpass, verified identical accuracy (0.9510).
   - RESOLVED: the causal bandpass filter's own gain/overshoot (worst case 13.7 across the pool) was silently clipped by reusing Q3.8 on its output -- confirmed real clipping inside 2 of vfdb/615's actual held-out test windows. The DC blocker's own output has the same character (worst case 8.9-9.9 across a 0.02-0.5 Hz cutoff sweep, ~0.001-0.003% of samples regardless of cutoff). Fixed with a uniform Q5.8 used at both points (not a patchwork of different widths); held-out accuracy unchanged (0.9510). A highpass-order sweep (1st/2nd/3rd) also confirmed the single-pole design has the lowest overshoot of the three, not just the lowest cost.
   - The 250->120 Hz resampling used here (both in testing and in this validation) is simple linear interpolation, which does not band-limit before downsampling. A live ADC sampling directly at 120 Hz needs its own standard analog anti-aliasing filter ahead of the ADC (true for any sample rate, not unique to 120 Hz) -- this was not an issue in testing (0 mismatches vs Python's properly anti-aliased resampler) because real recorded ECG has little energy above the new Nyquist, but should be designed deliberately, not assumed, in the final hardware front end.
   - This is a forced binary VT-vs-VF decision with no 'neither' option; Stage 1's gate wakes on non-VT/VF activity a meaningful fraction of the time (71.5% of gate activations in the full cascade test).
